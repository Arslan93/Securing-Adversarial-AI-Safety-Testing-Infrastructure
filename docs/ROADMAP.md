# Corrected original roadmap

The user's [original planning snapshot](ORIGINAL_PLAN.md) defines eight phases. The earlier drafts/cloning/reporting feature was mistakenly called Phase 6; it is an additional workflow, not a replacement for durable execution.

| Phase                            | Current scope and status                                                                                                                                                                                                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 — reliable local foundation    | Implemented and regression tested locally: modular atomic UI/API, configuration, health and accurate source/status handling.                                                                                                                                                                               |
| 2 — evaluation/policy workflow   | Core implemented: distinct scenarios, composer/import/versioning, private random canary, paired/partial attempts, rubric labels, policy diff and guarded comparisons. Broader evaluator calibration is separate work.                                                                                      |
| 3 — identity/scoped access       | Accounts, OIDC/MFA integration, memberships, ownership/grants and negative tests implemented. Identity tables are normalized; full domain-table normalization and external provider acceptance remain.                                                                                                     |
| 4 — runtime isolation/gateway    | Local four-container controls and actual boundary/cleanup tests pass. Ordinary containers and local probes do not establish independent host/side-channel attestation.                                                                                                                                     |
| 5 — evidence                     | Canonical packages, append-only history, separate signer and pinned verification implemented. Human-readable reports added. Independent signer administration and ZIP bundles remain.                                                                                                                      |
| 6 — durable execution/recovery   | Local single-broker durable queue, subprocess workers, leases, atomic reservations, original deadlines/budgets, partial attempts, linked retries, cleanup, operations UI and backup/restore drills implemented and tested. Distributed HA is outside this local scope.                                     |
| 7 — integrated hackathon release | Isolated demo seed/reset, five-account setup, two policy versions, approved corpus, committed browser regression, five-minute runbook, control-claim matrix and recorded fixture fallback prepared. Independent teammate handoff rehearsal remains an acceptance step.                                     |
| 8 — restricted pilot/production  | Local hardening implemented: strict pilot gates, protected file secrets, model approvals, containment, scoped retention/removal, deployment/preflight/CI and load/recovery tooling. Real external identity/TLS, independent signer/security review, ownership and production acceptance remain unapproved. |

Passing local tests does not make every PRD item or operational requirement 100% complete. Use the observed acceptance record and stated deployment conditions when presenting the project.
